# Extra peers for the second Bitcoin node.
#
# Empty, and expected to stay that way. The reasoning changed, so it is written
# out properly here rather than left standing in its old form.
#
# This file was once meant to hold a curated, signed list of nodes known to serve
# the chain the user's own node does not — on the assumption that during a split
# that chain might be hard to reach. The signalling figures make that close to
# backwards. Support for the new rules has not risen above a few per cent of
# blocks and no major pool is behind it, so once the chains separate it is the
# *enforcing* chain that will be scarce: few nodes, almost no hashpower.
#
# The chain this node follows is the other one — the one that keeps essentially
# all the hashpower and most of the nodes. That is the ordinary Bitcoin network,
# and ordinary peer discovery finds it without help. A curated list of peers for
# the majority chain would solve a problem that does not exist, and publishing
# one would name nodes for anyone wanting to attack that side of the split.
#
# So: no list, no signing machinery, and no addresses shipped with the software.
#
# ── Adding your own ───────────────────────────────────────────────────────────
#
# Still worth having, and unchanged. If the second node cannot find peers, or
# somebody you trust gives you an address during a split, add it. That path never
# depended on anyone else's list:
#
#   FORKTOWER_SQ_EXTRA_PEERS=host:port,host:port
#
# or the second node's settings on StartOS and Umbrel, or by adding lines to this
# file and rebuilding. One address per line, `#` for comments.
#
# Onion addresses are preferred. A second node following only the status-quo
# chain from the user's own network address links the two and marks its operator
# as someone with Lightning channels to defend, which is useful to exactly the
# wrong person.
#
# Whatever is listed here is passed to Bitcoin Core as `addnode`, never
# `connect`: `connect` would restrict the node to these alone and switch off peer
# discovery, turning a measure meant to prevent an eclipse into a single point of
# one.
